## [0.1.7] - 2026-11-20

### Added

- **`platform_managed` Remediation for Addon-Manager-Reconciled Workloads (`pkg/leeway`, `pkg/sources/topologydrift`, `pkg/kube`)**: A Deployment or StatefulSet whose own `metadata.labels` carry `addonmanager.kubernetes.io/mode: Reconcile` now gets a `platform_managed` remediation, with no `yaml` and no `command`, where it used to get a `manifest_patch`. The platform reconciles such a workload and can revert a patch, and on real GKE fleets most findings nobody planted were on `kube-system/kube-dns`, each offering one. The skew is real, so the finding stays, and its `summary` points at the node pools and the domains they span, or the addon's own configuration. Other remediation kinds, and the label's `EnsureExists` value, are unchanged. `topologydrift` reads the label from the Deployment and StatefulSet objects it already holds, and the field registry in `pkg/kube/transform_registry.go` records their `metadata.labels` as preserved. When `leeway report` cannot list those objects the `manifest_patch` is kept, and DaemonSets are not covered.

### Changed

- **Explicit Protobuf Content Types on Typed `client-go` Clients (`pkg/kube/client.go`, `pkg/report/collector.go`, `cmd/leeway/main.go`)**: `kube.BuildConfig` and `kube.BuildClientFromConfig` now set `AcceptContentTypes` to `application/vnd.kubernetes.protobuf,application/json` and `ContentType` to `application/vnd.kubernetes.protobuf` when a config leaves them empty, the setting `docs/leeway-design.md` §6.1 specifies. The generated calls leeway makes (the node, pod, workload and event lists, the informers' list and watch, SelfSubjectAccessReview) already negotiated protobuf, because client-go v0.37 asks for it by default when a config sets neither field, so their wire traffic is unchanged. Setting it on the config extends it to raw requests on a typed client, which today means discovery's group-version reads (`ServerResourcesForGroupVersion`, the check for whether the LeewayPolicy and ComputeClass CRDs are served): those now ask for protobuf too, and it stops leeway depending on that client-go default. A value the config already carries is kept, `BuildClientFromConfig` sets the defaults on a copy rather than on the caller's config, and a server that answers in JSON is still decoded, because client-go picks the decoder from the response's `Content-Type`. `leeway report`'s `client-go` path and multi-cluster `leeway watch` built their clients with `kubernetes.NewForConfig` directly and now go through `kube.BuildClientFromConfig` and `kube.BuildDynamicClientFromConfig`. The dynamic client, which reads the LeewayPolicy, ClusterLeewayPolicy and ComputeClass CRDs, stays on JSON: `dynamic.NewForConfig` replaces both content types with JSON whatever the config says (or JSON and CBOR when client-go's CBOR feature gates are on), never protobuf. Targets resolved in the kube-agents sandbox (`CREDENTIAL_PROXY_URL` set) still carry no rest config and are read through `kubectl`, unchanged.

## [0.1.6] - 2026-11-17

### Fixed

- **Paged `client-go` Snapshot Reads (`pkg/report/collector.go`, `pkg/kube/list_pages.go`)**: The `client-go` and dynamic list helpers `leeway report` uses when a target carries a rest config (nodes, pods, ReplicaSets, Deployments, StatefulSets, PersistentVolumeClaims, PersistentVolumes, events, LeewayPolicy, ClusterLeewayPolicy and ComputeClass) now page with `kube.DefaultPageLimit` and `Continue` through the new `kube.CollectPages`, which passes each page through a keep function before requesting the next. For the kinds `kube.Transform` trims (nodes, pods, ReplicaSets, Deployments, StatefulSets) that trims each page as it arrives; they called `List` with no `Limit`, so the whole untrimmed list sat in memory before one object was trimmed, the same shape #12 removed from the `kubectl` path. The other kinds are kept as decoded, as before, so for them only the size of each API response is bounded. An expired continue token (`410 Gone`) restarts the list once from the start and discards what was kept, so the result is never torn or duplicated. `kube.ListPages` is unchanged: it still hands untrimmed items to its callback only after every page has arrived, because that is what lets it promise a callback never sees a discarded item.
- **Paged `kubectl` Limit Recovery & `410 Gone` Restart (`pkg/report/collector.go`)**: `kubectlListPaged` now doubles `limit` back toward `250` on each successful page after a truncated outlier page (so a single oversized object no longer pins the remainder of a large list at a tiny page size), and restarts once cleanly from page 1 when the API server expires a `continue` token (`410 Gone` / `Expired`), discarding partial results to match `pkg/kube.ListAllPages` (`#13`).
- **Go 1.26.11 Toolchain Bump (`go.mod`, `Dockerfile`)**: Bumped Go from `1.26.10` to `1.26.11` to address stdlib `net/http` vulnerability `GO-2026-6859`.
- **Paged `kubectl` Snapshot Reads (`pkg/report/collector.go`)**: `fetchViaKubectl` now reads nodes, pods, events, ReplicaSets, Deployments, StatefulSets, PersistentVolumeClaims and PersistentVolumes one page of 250 at a time through `kubectl get --raw <path>?limit=250&continue=...`, and trims each page with `kube.Transform` before reading the next. A single `kubectl get pods -A -o json` made kubectl decode and re-encode the whole list, and leeway buffer and decode all of it, before one object could be trimmed, so a 23k-pod cluster drove a 2 GiB sandbox to `OOMKilled` with no report. Paged, the same cluster peaks at 264 MiB. A page the credential proxy truncates, or whose JSON ends early, is read again at half the size from the same continue token, which replaces the whole-list namespace fallback for these kinds; the LeewayPolicy and ComputeClass CRDs keep the typed read and that fallback.

## [0.1.5] - 2026-11-06

### Fixed

- **DaemonSet `metadata.name` Node Affinity & Asymmetric Zone Scoring (`pkg/sources/topologydrift`, `pkg/leeway`)**: Stripped the controller-injected `metadata.name` `matchFields` requirement from `DaemonSet` pods in `ConstraintsOf`, skipped `ClusterDefaultIntents` on `DaemonSet` pods, apportioned undeclared `DaemonSet` expectations by `WeightNodeCount` (`RequireSchedulable = false`, `NodeTaintsPolicy = Honor`), and excluded `SubjectDaemonSet` from `selector_confined` and `topologySpreadConstraints` manifest-patch remediations, eliminating false-positive `selector_confined` and Tier B drift findings on live GKE clusters.
- **API-Defaulted `NodeAffinityPolicy: Honor` Conflicting-Affinity Detection (`pkg/sources/topologydrift/resolve.go`)**: Checked resolved `opts.Policies.NodeAffinityPolicy == Honor` and `realUsableDomains` rather than `intent.Policies.NodeAffinityPolicy == ""` so conflicting `nodeAffinity` / `nodeSelector` rules under `topologySpreadConstraints` are detected on Kubernetes >=1.26 clusters where `kube-apiserver` defaults `nodeAffinityPolicy: Honor`.
- **`selector_confined` Rollout & Taint Counterfactual Guards (`pkg/sources/topologydrift/snapshot.go`, `pkg/sources/topologydrift/predicate.go`)**: Verified all `Running` pods across the distribution reside in the single eligible domain (`runningCount(dist) == Actual[0]`), honoured `NodeTaintsPolicy = Honor` when computing counterfactual unconstrained usable domains, and included `RequiredNodeAffinity` operators/values in `selectorDescription()`.
- **Proxied `kubectl` Non-Zero Truncation, Namespace Races & `LeewayPolicy` Collection (`pkg/report/collector.go`)**: Detected `credential proxy output truncated` even when `kubectl` exits non-zero, skipped vanishing `NotFound` namespaces and per-namespace `Forbidden` errors on best-effort resources during per-namespace fallback, and collected `LeewayPolicy` / `ClusterLeewayPolicy` CRDs in `fetchViaKubectl`.

## [0.1.4] - 2026-11-05

### Added

- **Single-Domain Selector Confinement Attribution (`pkg/leeway`, `pkg/sources/topologydrift`, `pkg/report`)**: Added `CauseSelectorConfined` (`selector_confined`) and `RemediationClusterNodes` (`cluster_nodes`) when `--topology-tier-c-signals` is enabled so multi-replica workloads with no spread intent that are confined to one failure domain by `nodeSelector` or required `nodeAffinity` (while counterfactual placement without that selector spans `>= 2` usable domains) emit an `info`-severity Tier-C `PlacementDrift` finding (`#4`, `#9`).

### Fixed

- **Hamilton Remainder Tie-Break & Auto-Capacity False Alarms (`pkg/leeway/apportion.go`, `pkg/sources/topologydrift`)**: Added `ApportionAligned` to break equal/near-equal largest-remainder tie bands toward domains that already hold more pods, and added `Intent.WeightingInferred` so `WeightAuto` capacity inference never penalizes workloads that already achieve zero-relocation equal spread across unequal-capacity domains (`#9`).
- **Proxied `kubectl` Output Truncation Fallback (`pkg/report/collector.go`)**: Scoped proxied `kubectl get events` queries to `--field-selector=involvedObject.kind=Pod`, omitted `-A` on cluster-scoped resources, detected `credential proxy output truncated` notices as well as JSON syntax/EOF truncation errors, and automatically fell back to cached per-namespace queries (`#9`).
- **Docs Drift Against the Code (`docs/site/src/content/docs/`)**: `agents.md`, `reference/finding-kinds.md`, `reference/cli.md`, `getting-started/report.md`, `concepts/scoring-and-attribution.md` and `concepts/tiers-and-intent.md` now match `cmd/leeway` and `pkg/leeway`: the report envelope is documented as snake_case (`schema_version`, `topology_findings`, `rank_findings`, `domains`, `summary.clusters_total`, …); `suspectedCause` lists the real vocabulary (`domain_outage`, `domain_capacity_shortfall`, `taint_exclusion`, `consolidation`, `volume_pinning`, `rollout_bias`, `constraint_ignored`, `selector_confined`, `unknown`) instead of names the binary never prints; `intent.source` / `confidence` / `weighting`, `remediation.kind` and the rank-finding fields are listed as emitted; the `report` flags are `--parallelism`, `--pretty`, `--namespace`, `--all`, `--min-drift` (there is no `--concurrency` or `--compact`) and `--clusters-from` takes `kubeconfig[:/path]`, `profiles:/path` or `<project>[/<location>]`, not a file; the `watch` flag table lists only flags the binary defines; the intent precedence list follows `IntentSource` order. All JSON examples are taken from a real `leeway report` run. `concepts/scoring-and-attribution.md` also explains why `excessSkew` can exceed `observedSkew` in `leeway report` (Pending/Unschedulable replicas are counted into the excess), and `TestCollect_CauseAttribution` pins that behaviour. The same corrections are applied to `README.md`, `index.mdx`, `getting-started/deploy.md`, `operations/observability.md`, `operations/tuning.md`, `operations/webhooks-and-sinks.md` and `reference/metrics.md`: `--metrics-addr` (not `--listen-addr`), `--cluster-name` (not `--cluster`), `--recovery-stable-for` default `2m` (not `--recovery-window 5m`), `--dedup-window` default `15m`; the `--topology-capacity-ratio`, `--topology-learn-baselines`, `--topology-baseline-*`, `--topology-per-domain-{min-drift,namespaces,exclude-namespaces,max-keys,collapse-states}` and `--topology-max-node-groups` rows are removed because the binary defines no such flags (their values are fixed defaults); the webhook open and resolved payloads are replaced with bodies captured from the `test/e2e` webhook receiver (no `schema_version`, `object_kind`, `object_name`, `summary`, `incident_id` or `*_seconds` fields exist on the wire). `reference/metrics.md` is regenerated from `topologydrift.MetricDocs()`, `computeclass.MetricDocs()`, `cmd/leeway/emit.go` and the OTLP export SLIs — 48 series with their exact types and label sets, the `cluster`-label rule (always in multi-cluster mode, only with `--cluster-name` in single-cluster mode), and the metrics the old page listed under names or labels that do not exist (`lookout_leeway_skew_observed`, `lookout_leeway_skew_excess`, `suspected_cause` on `alert_state`, `compute_class`/`rank_label` on the preference series) corrected.

### Changed

- **Conflicting-Affinity Remediation Payload (`pkg/leeway/remediation.go`)**: When a `topologySpreadConstraint` is contradicted by a `nodeAffinity`/`nodeSelector` on the same key, the `manifest_patch` remediation's `summary` now states that the affinity must be removed or widened first and that the `yaml` alone changes nothing, and the `yaml` opens with a comment saying the same. The finding never learns which selector entry to delete, so the removal cannot be rendered as a patch; the schema (`kind`, `summary`, `command`, `yaml`) is unchanged.
- **Report Test Fixture Names (`pkg/report/report_test.go`, `pkg/leeway/remediation_test.go`)**: Renamed the cause-attribution fixture (`TestCollect_SeededD` → `TestCollect_CauseAttribution`) and its workloads to names that describe the mechanism under test (`affinity-pinned-api`, `zonal-pv-store`, `cpu-starved-worker`, `pool-pinned-filler`, namespace `topology`) instead of a downstream evaluation fixture's names. Scenarios are unchanged.

- **Snapshot Report Thresholds & Causal Tier-C Surfacing (`pkg/leeway/score.go`, `pkg/sources/topologydrift/snapshot.go`)**: Added `ReportThresholds()` (`MinReplicasForScoring: 2`, `MinRelocationSmallN: 1`) for one-shot `leeway report` evaluations and surfaced breached Tier-C workload findings when positive causal attribution (`volume_pinning`, `domain_capacity_shortfall`, etc.) is present.

- **Unschedulable Shortfall Scoring for `DoNotSchedule` Spread Constraints (`pkg/sources/topologydrift/score.go`)**: Accounted for `Pending` (`Unschedulable`) pods blocked by a `DoNotSchedule` spread constraint and single-zone capacity starvation when only 1–2 replicas are `Running`.

## [0.1.0] - 2026-10-16

Initial standalone release of `leeway` (`github.com/go-steer/leeway`), extracted from `k8s-lookout` as a dedicated Kubernetes topology placement-drift and ComputeClass priority-rank analyzer and incident daemon.

### Added

- **Pure Scoring & Attribution Engine (`pkg/leeway`)**: Zero-Kubernetes-dependency placement drift and ComputeClass priority-rank evaluation engine (`Intent`, `Score`, `Judge`, `Attribute`, `AlertTable`, `BaselineTable`, `Finding`, `RankTracker`, `RankFinding`).
- **One-Shot Multi-Cluster CLI Mode (`leeway report`)**: Point-in-time snapshot evaluators (`topologydrift.EvaluateSnapshot` and `computeclass.EvaluateSnapshot`) and concurrent multi-cluster collector (`pkg/report`) producing structured `leeway.report/v1alpha1` JSON reports across `--clusters`, `--clusters-from`, `--profiles-dir`, `--kubeconfig`, `--context`, and `--in-cluster`.
- **Continuous Daemon Mode (`leeway watch`)**: Single- and multi-cluster shared informer loop with SQLite state persistence (`--store`), Prometheus `/metrics`, `/healthz`, `/readyz`, OTLP metric push (`--otel-exporter=otlp`), and HTTP webhook incident/resolution callbacks (`--webhook-url` / `--sink=webhook --sink-url=...`) carrying structured `leeway_finding` and `leeway_rank_finding` payloads.
- **Deployment & Observability Assets**: `LeewayPolicy` and `ClusterLeewayPolicy` CRDs (`deploy/crds/leewaypolicies.yaml`), Kustomize deployment manifests (`deploy/`), and prebuilt Grafana dashboard (`deploy/dashboards/leeway.json`).
